# Future enhancements (documented, not built)

Each item lists the expected benefit, cost and effort, and how it would plug into the existing adapter interface.
None is needed for the core scraper to work.

| Enhancement | Benefit | Cost / caveats | Effort | How it plugs in |
|---|---|---|---|---|
| **Apify actors** (Reddit, Facebook pages, Instagram, LinkedIn, X) | Reaches platforms and Reddit surfaces that free APIs cannot; maintained by third parties | ~$5/month free credit, then per-result pricing (reported ~$2–4 per 1,000 Reddit results). Running actors against platforms whose terms prohibit scraping is the user's legal responsibility; the project does not endorse it | Small | A new `ApiHandler` (`sources/apify.py`) calling the Apify run-sync API with `APIFY_TOKEN`, a hard `max_items` cap and a `plan()` of a few queries; results become `RawItem`s through the same pipeline. Off by default |
| **Reddit dump files** (Academic Torrents / Arctic Shift parquet) | Exhaustive, offline, deleted-content-free historical coverage for chosen subreddits; no rate limits | Multi-GB to TB; user must download; reported that Reddit began acting against public dumps in 2026; needs `zstandard` | Medium | `sources/reddit_dump.py`: a handler that streams a local `.zst` NDJSON file (path in settings), pre-filters lines by the anchor regex before JSON parsing and feeds `post_from_json`/`comment_from_json` |
| **Wayback Machine CDX** | Fetch pages that are now dead (404/410); discover old forum threads by URL pattern | Archive.org rate limits; URL-level only, no full-text search; must not be used to bypass a live site's robots.txt | Small | A `wayback_page` task type: on `FetchError(404/410)` in `web_pages`/`waterboards_docs`, query CDX for the nearest 2xx snapshot and parse it with the same extractors |
| **Common Crawl index** | Free URL discovery across a large crawl for configured forum domains | Index queries are URL/domain-based; WARC range fetches need care and bandwidth | Medium | A discovery task producing URLs for `queue_discovered_url` |
| **SearXNG (self-hosted) and Brave Search API** | More resilient search-engine discovery than `ddgs` | SearXNG needs a local Docker server; Brave needs a credit card (reported $5 monthly credit) | Small | Alternative `search_fn` for `DiscoveryProvider`, selected by environment variables |
| **Semantic relevance (model2vec or a small local embedding model)** | Catches paraphrased feedback with no system name and no keywords | Extra ~30–100 MB dependency; must be bounded so it cannot promote items without any context anchor | Medium | An optional second stage in `RelevanceScorer` adding a capped bonus for items that already have an anchor or thread context; guarded by `[ml]` extra |
| **OCR for scanned comment letters** | Recovers letters that are images (counted today as `wb_scanned_pdfs`) | Needs Tesseract or similar; slower; accuracy varies | Medium | In `WaterBoardsDocsHandler._run_wb_pdf`, run OCR when no text layer exists, then continue the same passage pipeline |
| **E-mailed comment letters** | Many recent letters are only released on request to `commentletters@waterboards.ca.gov` | A public-records style request by the user, not automation | Manual | Drop the received PDFs into a folder; a small `local_pdfs` source can ingest them with the existing letter pipeline |
| **Meta Content Library / TikTok Research API / Threads keyword search** | Public Facebook, Instagram, Threads, TikTok content | Research-institution affiliation or app review required; see [SOURCE_COVERAGE.md](SOURCE_COVERAGE.md) | Large, gated | Separate adapters if access is ever granted; outside this tool's free, key-light scope |
